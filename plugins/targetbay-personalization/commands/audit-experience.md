Use the `personalization-audit` skill.

Read consent state first — it bounds every recommendation below it, and a plan built on profiling that is
not permitted here has to be rewritten from the top.

Nobody has named the problem, so do not assume one and do not default to adding personalization. Removing
an element that costs attention and earns nothing is frequently the highest-value finding and the one
least often proposed.

Assess measurement discipline as its own dimension: a store that has never proved an onsite change does
not know which of its current elements help. Report the healthy dimensions as well as the broken ones, and
route every finding to the skill that owns it.

Analysis and recommendation only — no publishing, no live changes (`rules/safety-rules.md`).
